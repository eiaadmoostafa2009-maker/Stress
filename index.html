02 / PRESSURE

Three ways to put your endpoint under pressure.

Stress starts simple and scales with the complexity of your test. Check one request, generate sustained load, or describe complete virtual-user behavior with Lua.

01

Single Request

Fire a single request and inspect the response — status, headers, latency. Useful for checking an endpoint before turning up the pressure.

03 / VIRTUAL USERS

Simulate real user journeys, not just pings.

Virtual users walk through a sequence of requests that mirrors how real people interact with your service. Each step carries state, timing, and intent.

VIRTUAL USER — SESSION #1
01 GET / 200 12ms
02 GET /products 200 34ms
03 GET /products/42 200 28ms
04 POST /cart 201 67ms
05 POST /checkout ···

Beyond load. Behavior.

Traditional load testers hit one URL repeatedly. Stress lets you describe the full path a user takes through your system — with pauses, decisions, and state.

Each virtual user runs its own Lua script, maintaining cookies and session across requests. You test the system the way people actually use it.

04 / LUA

Describe the user. Not just the request.

Virtual users follow a Lua script that models a real session. Keep the scripting layer small, expressive, and familiar.

scenario.lua LUA 
 1-- virtual user scenario
 2-- each user runs this script independently
 3
 4request("GET", "/")
 5request("GET", "/products")
 6request("GET", "/products/42")
 7
 8sleep(0.5)  -- think time
 9
10request("POST", "/cart", {
11  body = '{"id": 42, "qty": 1}'
12})
13
14sleep(1)

Lua, not JavaScript.

Your test scenarios stay small and readable. Lua is lightweight, embeddable, and already proven in high-performance tools. No Node.js runtime, no dependency trees, no bundler.

Write what a user does — Stress handles the concurrency, timing, and metrics.

06 / WHY STRESS

Built for developers. Not for procurement.

Stress is an open-source load-testing tool designed for developers and small teams who want useful load testing without enterprise overhead.

OPEN SOURCE

Inspect it, run it, modify it, and build around it. MIT licensed, no vendor lock-in, no telemetry.

LIGHTWEIGHT

Single binary, no runtime dependencies. Runs on your laptop, CI server, or a \$5 VPS without breaking a sweat.

SCRIPTABLE

Use Lua when a simple request is no longer enough to represent the behavior you want to test. Small language, big flexibility.

HONEST METRICS

Latency percentiles, throughput, error rates — not averages that hide tail latency. See how your service really performs under pressure.

OPEN SOURCE

Run it. Read it. Build on it.

Stress is open source and available on GitHub. Download the latest release or clone the repository.
